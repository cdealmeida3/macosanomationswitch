# macOS animation settings: catalog for macOS 27 Golden Gate and macOS 26 Tahoe

Research date: 2026-11-14.

## 1. Target releases

**How much evidence exists:** Hardly any published source tests these keys one by one on 26 or 27. Most 2025–2026 material is dotfiles and blog lists that copy the same commands without showing results. The table marks each key:
- **reported**: someone states it was run or checked on that release.
- **listed**: it appears in a 2025–2026 guide for that release, but no result is shown.
- **unverified**: no recent evidence found.

## 3. Reduce Motion: can a third-party app set it?

- **No public setter API.** AppKit exposes only the read-only `NSWorkspace.shared.accessibilityDisplayShouldReduceMotion`, plus `NSWorkspace.accessibilityDisplayOptionsDidChangeNotification` on the workspace notification center. Example of read-only use: [gpui-base reduce_motion.rs](https://docs.rs/crate/gpui-base/0.7.0/source/src/reduce_motion.rs).
- **`defaults write` / CFPreferences without Full Disk Access fails** on 26.x and, by the Oct 2026 report, on 27. The `defaults` error is "Could not write domain com.apple.universalaccess; exiting". cfprefsd rejects the write and no TCC prompt appears ([smarkovik PR #18](https://github.com/smarkovik/mac-setup/pull/17) attributes this to a `com.apple.macl` gate on the plist). Running as root/`sudo` does not help ([mathiasbynens/dotfiles #1039](https://github.com/mathiasbynens/dotfiles/issues/1039), [#1027](https://github.com/mathiasbynens/dotfiles/issues/1027)). An unsigned or ad-hoc-signed app is in the same position as Terminal. It would need the user to grant it FDA, and the TCC grant for an ad-hoc-signed app is tied to its code hash, so it is lost on every rebuild.
- **FDA helps on Sequoia 15.8** ([gameshler/macsetup PR #9, Sep 2026](https://github.com/gameshler/macsetup/pull/9): "reads back correctly" after the grant). On Tahoe the reports are mixed ([nix-darwin #1049](https://github.com/nix-darwin/nix-darwin/issues/1049)). On 27, unverified.
- **A successful write may still not take effect live.** System Settings also updates `com.apple.Accessibility ReduceMotionEnabled` and notifies the accessibility daemons. A raw plist or preference write does neither, so expect to need a logout or app relaunches.
- **Shipping workaround:** [MonkShift (2026, macOS 14+)](https://github.com/gslava/MonkShift) avoids protected preference writes. It uses Accessibility permission (UI scripting) to flip the Reduce Motion switch in System Settings, then confirms the change through the native getter. Mainspring, a commercial app, also offers a one-switch Reduce Motion but does not document how it works.
- MDM configuration profiles (`com.apple.universalaccess` payload) are another possible route, not researched here.

## 4. Writing other apps' domains (com.apple.dock, NSGlobalDomain) from a non-sandboxed app

- **Works and needs no permission prompt.** `CFPreferencesSetAppValue(key, value, "com.apple.dock")` (or `CFPreferencesSetValue(…, kCFPreferencesAnyApplication, kCFPreferencesCurrentUser, kCFPreferencesAnyHost)` for NSGlobalDomain), followed by `CFPreferencesAppSynchronize`, goes through cfprefsd exactly like `defaults write`. Apple's CFPreferences docs let you pass any application ID ([Preference Domains](https://developer.apple.com/library/content/documentation/CoreFoundation/Conceptual/CFPreferences/Concepts/PreferenceDomains.html)).
- Shipping 2026 tools write `com.apple.dock` `autohide-delay` and `autohide-time-modifier` and reload the Dock without FDA or admin rights ([MonkShift ARCHITECTURE.md](https://github.com/gslava/MonkShift/blob/main/docs/ARCHITECTURE.md): "No SIP changes or administrator privileges").
- **Sandboxed apps** would need the `com.apple.security.temporary-exception.shared-preference.read-write` entitlement, which the Mac App Store generally does not accept ([Apple DTS on a forum thread, Mar 2026](https://developer.apple.com/forums/thread/820101)).
- **Exceptions are TCC/container-protected domains:** `com.apple.universalaccess` (see §3) and `com.apple.mail`, whose preferences live in `~/Library/Containers` (both fail on 26.6.2 per smarkovik PR #18). Safari is similar and is not needed here.
- **Use CFPreferences, not direct plist edits.** cfprefsd caches values, so editing `~/Library/Preferences/*.plist` directly can be overwritten. The codex issue needed `killall cfprefsd` after such edits.
- **Restarting processes:** `killall Dock` restarts the Dock. Most NSGlobalDomain keys are read by each app at launch, so already-running apps keep the old behaviour until they are relaunched. There is no supported "reload preferences" broadcast for them.

## 5. Other caveats

- **Spaces slide speed cannot be changed.** No defaults key affects it on Tahoe or Golden Gate. Reduce Motion only turns it into a cross-fade, with a pause still reported ([Apple Community, Nov 2025](https://origin-discussions2-us-dr-prz.apple.com/thread/256195960); [HN on Golden Gate](https://news.ycombinator.com/item?id=49894005)).
- **`defaults write` exits 0 even for a key nothing reads**, including a misspelled one ([gameshler PR #9](https://github.com/gameshler/macsetup/pull/9)). Example: Mainspring prints `com.apple.universalaccessReduceMotion` with no space between domain and key. A read-back check is not proof that a setting has any effect. An app can verify Dock or AppKit behaviour only by observing it.
- **For restore,** record whether each key was absent before changing it (MonkShift does this) and `delete` rather than write a guessed default. Defaults differ between sources (for example autohide-time-modifier 0.5 vs 1).
- **The 2026 lists of Tahoe "tweaks" are largely copied from old lists.** Several still include Launchpad keys that cannot work on Tahoe. Treat "listed" entries as plausible but untested, and verify keys 1–8 and 16 on real 26.x and 27.x hardware before shipping.
- **`com.apple.SwiftUI.DisableSolarium`** appears in Tahoe tuning lists as a Liquid Glass opt-out. It is a visual-effects key, not an animation key. Not researched.
